## 版本摘要

Local GitHub Library 0.2.6 新增错别字容错搜索，并启用新的多分辨率应用图标。精确结果不足时，程序会使用本地技术词库纠正 1–2 个英文字符后再查询一次；原有精确结果始终优先。搜索、榜单、收藏、报告和独立模型发布方式保持不变。

## 主要更新

- 新增英文关键词拼写纠错，支持漏字、多字、错字和相邻字母颠倒。
- 支持多词逐词纠正，例如 `machine learnign` 会按 `machine learning` 尝试搜索。
- 原始精确结果始终排在前；只有结果不足时才增加一次纠正查询。
- 三位以内的缩写不会自动替换，避免误改 `jev` 等短关键词。
- 内置常见技术词库，并从搜索结果的 Topics 和仓库名称中持续学习新词。
- 学到的技术词保存在本地 `search-vocabulary.txt`，重启后仍可使用。
- 搜索界面会显示 `原始关键词 → 纠正关键词`，并提示已启用拼写纠错。
- EXE、窗口标题栏、Windows 任务栏和系统托盘统一使用新的多分辨率应用图标。

## 问题修复

- 修复输入一个字母错误或多余字母时搜索结果直接为零的问题。
- 修复本地整词过滤在轻微拼写偏差下过滤全部候选的问题。

## 兼容性与升级

- 从 0.2.5 升级不需要迁移收藏、备注、报告、Star 快照、提示词、榜单缓存或 `.ghconfig` 数据。
- 直接替换 EXE 时，请保留同级的 `runtimes` 目录。
- 搜索词库是本地辅助缓存，不会上传到第三方服务。
- 本地 LLM 仍是可选独立下载，不包含在 0.2.6 标准包中。

## 平台与限制

- Windows 10/11 x64。
- 程序为自包含发布，不要求预装 .NET。
- 搜索、当前榜单和 README 读取需要访问 GitHub。
- 首次搜索非常冷门且尚未收录的技术词时，自动纠错可能无法给出候选。
- 未签名 EXE 可能触发 Windows SmartScreen 提示。
- 当前仓库尚未声明开源许可证。

## 验证结果

- `unitty → unity`、`pythno → python`、`kubernets → kubernetes` 测试通过。
- 多词逐词纠错和三字母短词保护测试通过。
- 本地技术词库学习与重新载入测试通过。
- UI、收藏、排序、设置、托盘和紧凑布局测试通过。
- EXE 内嵌图标与 16–256 像素 ICO 结构检查通过。
