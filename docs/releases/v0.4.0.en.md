## Summary

Local GitHub Library 0.4.0 adds a complete local notes workspace and upgrades note storage to a folder-based Markdown and image repository. Notes support a folder tree, drag ordering, inline images, bold text, colors, auto-save, encryption, and context actions. This release also adds single-instance protection, verified atomic writes, index backups, and corruption detection.

## Highlights

- Add a Notes workspace alongside Search, Rankings, and Favorites.
- Organize notes in nested folders with creation, deletion, and long-press drag ordering.
- Save every note as a same-named `.md` file with related images in a sibling `images` directory.
- Paste images into the body, copy the actual bitmap, zoom with Ctrl+wheel, and persist inline images.
- Add bold text, six text colors, and `Ctrl+S`.
- Keep the three-minute auto-save interval and prompt when unsaved changes remain before exit.
- Add right-click actions for opening, saving, moving, deleting, creating notes and folders, and Open With.
- Open note files with the default program, Notepad, Visual Studio Code, or File Explorer.
- Encrypt notes with PBKDF2-SHA256 and AES-GCM; encrypted Markdown and images are stored as `.md.enc` and `*.png.enc`.
- Require the correct password again before deleting an encrypted note.
- Include normal notes, folder hierarchy, images, encrypted notes, and rich-text metadata in `.ghconfig` exports.

## Fixes

- Align note deletion controls across folder depths.
- Normalize mixed font family, weight, and color after pasting while preserving intentional formatting.
- Display encrypted note images instead of literal Markdown after reopening.
- Prevent password-dialog action buttons from being clipped.
- Animate neighboring notes during same-folder drag ordering.
- Keep notes visually attached to their actual parent folder instead of stacking them below the deepest folder.
- Prevent multiple application instances from writing the same local library.
- Verify and atomically replace the notes index, Markdown, images, and encrypted files, while retaining an index `.bak` backup.
- Fall back to the index backup when the primary index is damaged and stop writing if no valid copy remains.

## Compatibility and upgrade

- Upgrading from 0.3.1 does not require reimporting reports, favorites, notes, Star snapshots, prompts, or ranking caches.
- Existing plaintext notes migrate to folders, Markdown, and images on first load.
- A legacy encrypted note cannot reveal its title without the password, so it initially receives a secure placeholder folder and is renamed after unlock and save.
- Note storage changes substantially. Export a `.ghconfig` or copy the whole `GitHubReports` directory before upgrading.
- Run only one application instance during the upgrade.
- Keep the `runtimes` directory beside the executable when replacing only the EXE.
- The local LLM remains an optional separate download and is not included in the standard package.

## Platforms and limitations

- Windows 10/11 x64.
- Encryption protects note text and image contents; titles, folder names, and file counts may remain visible in local paths.
- A forgotten note password cannot be recovered.
- The notes workspace works offline; GitHub search and rankings still require network access.
- The unsigned executable may trigger a Windows SmartScreen warning.
- The repository does not currently declare an open-source license.
